# 乗車券の年齢区分・割引

現在の有効範囲は `/fare/ticket` のみ。分割・定期券・事前計算運賃は大人・割引なしを維持する。

## 共通処理

- Goの `TicketPricingOptions` と `TicketDiscounts` が割引の条件を管理する。JR営業キロ・JR会社集合は補正後の運賃計算結果から取得する。私鉄は別の端数処理単位として保持する。通常・補正禁止では新幹線エッジを保持し、折り返し控除が成立する区間だけ在来線へ変換する。会社は市内駅展開後を含む計算経路のエッジから取得する。重複検証は別の経路を全展開して控除後に行い、最安の在来線券採用も通常の補正とは別に実行する。第69条・第70条は判定時だけ展開駅列を参照し、特例に関係しない新幹線エッジを保持する。
- JR運賃（加算運賃・バリアフリー料金込み）を小児化してから選択割引を適用する。それぞれ10円未満切り捨て。私鉄は小児化だけ行い、津幡―高岡の特定運賃は調整後の合計を小児化する。
- `CalculateWithPricing` は運賃ページの入口。既存の `Calculate`・`Split` は従来のまま。将来の分割対応では、候補券の評価に共通の割引処理を接続し、大人運賃で分割した結果への後掛けは行わない。
- `firstPricingExtension` は片側を延長して閾値を満たす発売可能な1候補を返す共通探索。近郊区間の補正器も検索単位で複製し、共有オブジェクトの料金設定を変更しない。

## 最安探索

大都市近郊区間内完結の場合は、割引の有無によらず延長しない。

補正後のJR営業キロが100キロ未満で、選択割引の閾値が100キロの場合だけ、次の順で比較する。

1. 経路通りの運賃
2. 元の入力経路の着駅側を延長し、補正後のJR営業キロが100キロを超える最初の発売可能な1経路
3. 元の入力経路の発駅側を同様に延長した1経路

安くなった場合だけ結果を更新する。同額は先の経路を維持する。発着の両側を同時に伸ばさず、各方向で複数の閾値到達経路を比較しない。それ以外（100.0キロちょうどを含む）は既存の114条の延長処理を割引後運賃で評価する。閾値延長と114条を重ねて探索しない。

各候補全体に通常補正・市内駅等の特例を適用し、会社・JR営業キロ・発売可能な経路を確認する。候補比較で作った券面と金額をそのまま返す。重複控除が次の1駅で成立する中間状態は探索に残す。

閾値延長は駅ID順の幅優先で最初の有効候補を決める。各方向10万状態を超える場合は明示的なエラーとし、途中結果を完了扱いにしない。運賃ページのWorkerは独立させ、条件変更・画面終了で探索を停止できる。

## 接続

`calculateRouteTicket` に `passengerType`（`adult` / `child`）と `discountId` を渡す。未指定は `adult` / `none`。結果の `fare` が適用後の金額、`discountApplied` が選択割引の適用フラグ。小児化だけではフラグを立てない。適用された場合は運賃の下に割引の略称を表示する。条件未達理由は表示しない。

URLにも同名のキーを用いる。未知のURL値は既定値、不明なWASM入力値はエラー、小児不可の割引は `none` に正規化する。利用日・会員資格・証明書・同伴条件は入力・判定しない。

## 発着別の単駅指定

`/fare/ticket` の詳細オプションから、乗車駅・降車駅をそれぞれ単駅指定できる。WASM入力の `departureSingleStation`・`arrivalSingleStation` は真偽値で、未指定は両方 `false`。URLにはオンの項目だけ同名のキーで `=true` を保存する。

指定側の特定都区市内・東京山手線内（第86・87条）と大阪・新大阪（第88条）への補正を抑止する。通常・最安・補正禁止の各モードと近郊区間専用の特例処理に反映し、反対側の特例は維持する。最安モードの経路延長は引き続き許可し、延長後の候補にも同じ側の設定を適用する。候補比較から券面・距離・金額の算出まで検索単位の設定を使用する。
