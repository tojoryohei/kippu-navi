# 駅候補の仮想化の検証（2026-10-10）

## 実装

運賃・分割計算・分割禁止駅で共通の `StationMenuList` を使用する。11件以上の候補では表示範囲と上下5行、範囲外のフォーカス行だけを描画する。10件以下は測定処理の負担を避けて通常描画する。

駅名・ふりがなの全文と折り返しを維持し、ResizeObserverによる実測で行の高さを更新する。検索条件、候補数、順序は変更しない。同名の「燕三条」が運賃データに2件あるため、駅の選択値とreact-selectの候補キーを併用して識別する。

react-select内部の全件検索とReact要素生成は残る。今回の比較は仮想化全体の効果であり、検索とReact描画の時間を個別に断定するものではない。

## CIのタッチテスト修正（PR #813）

初回CI（Actions run 38056543378）は106件中105件成功し、タッチスクロール1件のみ失敗した。`Input.synthesizeScrollGesture` の呼び出し後もメニューのscrollTopが0のままで、ローカルで記録した既存3件の失敗はCIでは発生していない。

タッチ対応のモバイルコンテキストを起動時から指定し、フォントと描画の完了を待って、開始座標がメニュー内にあることを確認するよう変更した。一括ジェスチャーを `Input.dispatchTouchEvent` の押下・10段階の移動・離す操作へ置き換え、各移動を別フレームで処理する。scrollTopが0から50px超へ増えることと、候補の描画数が制限されていることを検証する。アプリケーション側の動作は変更していない。

修正後のタッチ操作はローカル10回連続成功。最終の仮想化テスト8件もすべて成功し、lintと既存調査ファイルを除いた型チェックも成功した。Linux上の合成ジェスチャーが移動しなかった内部要因までは特定していないため、更新後のCI結果とは区別する。
