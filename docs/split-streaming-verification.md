# 経路自動検索の段階表示 — ローカル検証

2026-10-24

## 動作

- 経路入力検索は進捗と結果整理中の表示を経て、全件完了後に結果を一括表示する。経路入力専用の途中通知は削除した。
- オンラインの経路自動は従来どおりAPI応答を待ち、WASMの詳細計算から通知する。HTTP APIは変更しない。
- オフラインの経路自動も比較対象全体の最安金額が確定してから通知する。
- 経路自動検索では初回1件を即時通知し、以降は100ms経過または50件蓄積時、最後に残件を送る。Goの同期呼び出し中は各解が完成した時点で経過時間を判定する。
- 経路自動検索の途中通知は差分のみ。完了通知では全結果を再送しない。UIは完成順を維持し、残件の失敗時にも結果を残す。
- 表示用の運賃要約が同じでも、途中経路の異なる解は識別して保持する。
- 分割前の運賃計算に失敗した場合は、分割候補の計算・通知を開始せず終了する。在来線で接続しない区間は、オンライン・オフラインとも経路入力検索を案内する。

## 実WASMの測定

`RUN_PERFORMANCE_TESTS=1 GOCACHE=/tmp/kippu-go-cache npm run test:dev -- split-streaming`

Playwrightで実際のGo/WASMを使用し、Workerへの計算要求から測定した一回分の例。初回描画は結果DOMを検出した次のanimation frameで観測した。オンラインの値にはAPI応答待ちとエンジン準備を含めない。オフラインは端末内探索を含む。

| 方式・条件 | 解数 | 初回結果受信 | 初回描画観測 | 全件完了通知 |
| --- | ---: | ---: | ---: | ---: |
| オンライン自動・東京→大宮 | 9 | 63.3ms | 93.2ms | 276.1ms |
| オフライン自動・東京→大宮 | 9 | 1,416.4ms | 1,439.1ms | 1,611.1ms |

オンライン・オフライン自動の多解ケースでは全件完了前の描画を確認した。経路入力検索は一括表示に戻し、進捗100%・結果整理中にはまだ結果を表示せず、完了通知で表示することをブラウザテストで確認した。

これらはローカルの一回測定であり、端末・経路・解数に依存する。従来実装との速度比較や本番環境の測定ではない。

## 回帰検証の範囲

- Go：経路自動の最安確定後の通知、後の候補経路が安い場合、全解の一致、分割回数・禁止駅。既存のGo全テストと変更パッケージのrace検査。
- Worker：最初の即時通知、時間・件数によるまとめ送り、重複排除、終端までのリクエスト保持。
- ブラウザ：経路入力の完了時一括表示、経路自動の結果の追加、開閉状態の保持、途中失敗、再計算、古い通知の破棄、既存の経路指定・詳細条件。
- 実WASM：乗車券・定期券・IC定期券の逐次結果と従来の全件結果の一致。詳細復元とオフライン探索の両方を確認。

描画時間の比較は端末負荷に依存するため、通常実行では省略し、上記の環境変数で明示実行する。定期券のWASM比較は通常1箇月・IC6箇月の代表条件とし、期間ごとの探索条件は既存Goテストで検証する。

デプロイ・本番検証は行っていない。
